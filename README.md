# INEZA MUGISHA ALLEN — Family Legacy

A starter full-stack family website using Firebase Hosting, Firebase Authentication,
Cloud Firestore, Cloud Storage rules, and Cloud Functions.

## What is included

- Premium responsive family website front end.
- Firebase email/password sign-in and email verification.
- One-use, seven-day invitation tokens generated by the owner.
- Server-verified invitation redemption; invite email must match the verified account email.
- Custom roles: `owner`, `admin`, `member`, `guest`.
- Owner-only role changes and account disabling via Cloud Functions.
- Firestore and Storage rules that deny access by default.
- Private document storage path reserved for owner-only files.
- Basic security headers on Firebase Hosting.
- Owner bootstrap script that runs only from a trusted machine.

## Important limits

This is a deployable starter, not an already-live website. You must create and configure a Firebase project,
add its web configuration to `public/app.js`, enable Authentication, create Firestore and Storage, deploy
rules/functions, and bootstrap the owner. Do not put family documents or credentials in a public GitHub repo.

The current front end includes invitation creation and role management. It does not yet provide a full
content editor, photo uploader, or member directory. Those should be added only with explicit permissions
and tested security rules.

## Step 1 — Install prerequisites

Install Node.js LTS and Git. In a terminal, inside this folder run:

```bash
npm install
cd functions
npm install
cd ..
```

## Step 2 — Create Firebase project

1. Open https://console.firebase.google.com/ and create a project.
2. Add a Web App and copy its Firebase configuration.
3. In Firebase Console > Authentication > Sign-in method, enable Email/Password.
4. In Authentication settings, configure authorized domains and email verification.
5. Create a Cloud Firestore database.
6. Set up Cloud Storage.
7. Billing may be required for Cloud Functions deployment; check current Firebase plan requirements.
8. Paste the web app config into `public/app.js`. Never paste a service-account private key into browser code.

## Step 3 — Select your Firebase project

Install/initialize Firebase CLI and sign in:

```bash
npx firebase-tools login
npx firebase-tools use --add
```

Choose the project you created. If needed, create `.firebaserc` using `.firebaserc.example`
as a starting point and replace the placeholder with your project ID.

## Step 4 — Deploy the backend and rules

```bash
npx firebase-tools deploy --only firestore:rules,storage,functions,hosting
```

Wait for deployment to finish. Review errors rather than assuming deployment succeeded.

## Step 5 — Create your owner account safely

1. Open your deployed site and create your own account using your real email.
2. Verify your email.
3. In Firebase Console > Authentication > Users, copy your account's UID.
4. Create a service account key from Firebase Project settings > Service accounts.
5. Save the key OUTSIDE this project folder, such as `C:\secure\firebase-admin-key.json`.
   Never upload it to GitHub or send it to anyone.
6. Set environment variables in PowerShell:

```powershell
$env:GOOGLE_APPLICATION_CREDENTIALS="C:\secure\firebase-admin-key.json"
$env:FIREBASE_PROJECT_ID="your-real-project-id"
$env:OWNER_UID="paste-your-authentication-uid"
node scripts/set-owner.mjs
```

Use your actual values. The script assigns the owner claim to that UID. Sign out and sign in again
to refresh the ID token. Protect the service account key and delete it from the computer when it is no longer needed.

## Step 6 — Invite family members

1. Sign in as the owner.
2. In Owner controls, enter the relative's email.
3. Choose `member`, `guest`, or (only when needed) `admin`.
4. Click Create invitation.
5. Send the returned token privately to the intended relative.
6. They create an account with the same email, verify it, sign in, and redeem the invitation.
7. Never send the owner's password or service-account key.

The invitation token is a bearer secret. Send it only to the intended person. Tokens expire after seven days
and can be used once.

## Roles

- `owner`: full application control; only assigned through the trusted bootstrap process.
- `admin`: limited server functions, including post moderation. Cannot invite users or change roles.
- `member`: read shared family posts and create posts under the current rules.
- `guest`: no family-post access under the current Firestore rules; intended for future limited public/shared views.

## Security checklist before using real family data

- Enable Firebase App Check and enforce it for supported services/functions after testing.
- Configure strong account recovery and multifactor authentication where available.
- Test Firestore and Storage rules with the Firebase Emulator Suite.
- Review Firebase Authentication authorized domains.
- Never allow browser clients to write their own role or custom claims.
- Review audit logs and access permissions regularly.
- Set up billing alerts, budget notifications, backups, and a recovery plan.
- Use a private GitHub repository if source code contains non-public details; do not commit secrets.
- Do not put sensitive documents in public hosting folders.

## Local emulator

```bash
npx firebase-tools emulators:start
```

The app's Firebase config and emulator connections must be configured for local testing before using the emulator.
